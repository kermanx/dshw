# 修复自动评审意见（不提交、不推送）

唯一目标仓库是 `{{clonePath}}`，它是 PR #{{prNumber}} 的分支 `{{branch}}`（目标分支 `{{baseRefName}}`）。你当前就在这个仓库中运行。

dshw 刚刚对这个 PR 的最新提交跑了一次自动代码评审，评审意见在最后。评审只看到了当时提交的 diff，可能不完全了解上下文，也可能判断有误。

## 任务

1. 先用 `gh pr view {{prNumber}}`、`git log`、`git diff` 弄清这个 PR 想实现什么，再逐条判断评审意见是否成立。
2. 成立的：按最小改动修复，保持 PR 原有意图和已有行为；不要为了让意见消失而删除、绕过或弱化功能。
3. 不成立的：不要修改代码，在最终结果里说明理由。
4. 与其他需求冲突、或需要产品决策才能定的：不要猜，把该条标为无法处理并说明原因。
5. 只处理评审意见涉及的内容，不要顺手重构无关代码。

## 重要：不要提交、不要推送

- **不要** `git commit`、**不要** `git push`、**不要** force push、**不要**创建 PR 或改动 PR 状态。
- 改动就留在工作区（未提交状态），dshw 会读取 `git diff` 给用户看，用户确认后再决定是否推送。
- 不要 `git checkout` / `git reset` / `git stash` 丢弃工作区改动。

## 完成条件

完成必要修改和最小验证（只验证受影响的模块，不需要全量测试）后，直接输出本轮结果并结束，等待 dshw 的下一条指令。

最终回复最后一行必须是：

`DSHW_RESULT: completed`

如果经过调查后确认任务无法安全完成，停止继续尝试，不要伪造成功；最终回复最后两行必须严格是：

`DSHW_RESULT: blocked`
`DSHW_REASON: <用一行说明无法完成的具体原因>`
