# 修复 PR CI

唯一目标仓库是 `{{clonePath}}`，它是 PR #{{prNumber}} 的分支 `{{branch}}`，该 PR 的 CI 已经全部运行完，其中有失败。

你当前就在这个目标仓库中运行。开始修改前，先用 `gh` 和 Git 查看 PR #{{prNumber}} 的标题、描述、提交和 diff，弄清这个 PR 想实现什么；修复 CI 时必须保留该意图和已有行为，不能通过删除、绕过或弱化 PR 的功能来让检查变绿。

请使用 gh 查看 PR #{{prNumber}} 的失败 checks 和日志，定位并修复失败。

你不需要做全量的测试和检查，只需要检查有出错的模块。当你认为你的修改已经完成时，就请提交并 push 当前分支。你不需要等待 CI 运行结果，也不需要检查 review 意见。

不要修改无关内容，不要 force push。

如果任务能够完成，最终回复最后一行必须是：

`DSHW_RESULT: completed`

如果经过调查后确认任务无法安全完成，停止继续尝试，不要伪造成功，也不要 push 不完整的结果；最终回复最后两行必须严格是：

`DSHW_RESULT: blocked`
`DSHW_REASON: <用一行说明无法完成的具体原因>`
